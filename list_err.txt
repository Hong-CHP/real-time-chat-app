  Backend Bugs

  1. Refresh token flow is broken: backend/src/auth/auth.controller.ts:34 uses req.cookie?.refresh_token, but Expres
     s/Nest uses req.cookies when cookie-parser is installed. I also don’t see cookie-parser registered in backend/s
     rc/main.ts:1. Result: /auth/refresh always fails, so frontend token refresh will not work.
  2. User routes are ordered incorrectly: backend/src/users/users.controller.ts:30 defines @Get(':id') before
     @Get('search') and @Get('me'). /users/search and /users/me can be captured as id, causing wrong handlers or
     admin guard failures.
  3. Delete “me” passes the whole user object instead of the id: backend/src/users/users.controller.ts:66. removeMe()
     expects a number, but receives me.
  4. Backend type-check fails in the test suite: backend/src/users/users.service.spec.ts:36 calls
     service.create({ email, password }), but CreateUserDto requires name.
  5. sendRequest() swallows non-duplicate Prisma errors: backend/src/friend/friend.service.ts:48. If the error is not
     P2002, the method returns undefined instead of throwing.
  6. Chat gateway checks membership with data.roomId instead of normalized roomId: backend/src/chat/
     chat.gateway.ts:128. If the client sends a string room id, this may fail even though Number(data.roomId) was
     valid.

  Frontend Bugs

  1. Chat violates React hook rules: frontend/src/pages/Chat.tsx:49 returns before later useEffect hooks at lines 57,
     112, and 125. ESLint confirms this. This can cause unstable renders when auth state changes.
  2. Private room names are broken: frontend/src/pages/Chat.tsx:253. filter() returns an array, but the next line
     uses otherMember?.user.name. That will be undefined; likely you wanted otherMember[0]?.user.name.
  3. Message alignment is probably wrong: frontend/src/pages/Chat.tsx:269. Backend message senderId is a number, but
     frontend userId from JWT decode may not match the declared string type. Strict === can make your own messages
     appear as other users’ messages.
  4. Sending before entering a room is not blocked: frontend/src/pages/Chat.tsx:102. It only checks currentRoomId ===
     -1, but the initial value is null, so it can emit a message with roomId: null.
  5. Production startup likely uses the wrong React renderer: frontend/src/main.tsx:15. hydrateRoot is used in
     production, but frontend/index.html:10 has an empty root. Unless you have a real SSR server injecting HTML,
     production should not hydrate an empty SPA root.
  6. apiFetch() refresh depends on the broken backend refresh endpoint: frontend/src/context/api.ts:22. Any expired
     access token will redirect to login instead of refreshing.
